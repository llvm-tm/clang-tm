The manual version successfully completes millions of transactions with correct invariants. The plugin version crashes immediately due to a fundamental flaw in how it generates retry logic for nested transactional functions.

## Root Cause: Plugin's Flawed Retry Logic

### Transaction Structure
```cpp
// Main loop in worker_thread
while (!stop_workers) {
    double roll = dist(rng);
    int aborted = sigsetjmp(longjmp_buf, 0);

    if (!aborted)
        tinystm::begin();  // ← SINGLE tm_begin() call per iteration

    // Helper functions called HERE
    if (roll < threshold)
        total_transactional();  // ← NOT wrapped in TX
    else
        transfer(src, dst, 1);  // ← NOT wrapped in TX

    tinystm::commit();  // ← SINGLE tm_end() call per iteration
}
```

### Helper Function Implementation
```cpp
void transfer(int src, int dst, int amount) {
    // Directly calls tinystm:: methods
    // No transaction boundary - relies on outer transaction
    uint32_t balance = tinystm::tm_read_i4(&a_src->balance);
    balance -= amount;
    tinystm::tm_write_i4(&a_src->balance, balance);
    // ... more reads/writes
}
```

### Key Characteristics
- **ONE transaction boundary per iteration** (in the loop)
- Helper functions (`transfer`, `total_transactional`, `reset`) are **NOT** transaction-annotated
- Direct calls to `tinystm::tm_read_i4` / `tinystm::tm_write_i4`
- Works correctly - reaches 6M+ transactions with proper invariants

## Plugin-Instrumented Version (bank.cpp with LLVM plugin) - FAILS ✗

### Transaction Structure Generated by Plugin
The plugin creates separate transaction boundaries for EACH `@TX` annotated function:

```cpp
// Generated for do_transaction_work (TOP-LEVEL)
%counter = load i32, @tm_nested_call_counter
if (counter == 0)  // outer path
    sigsetjmp(...)
    counter = 1
    tm_begin()  // ← FIRST tm_begin() call
else               // nested path
    counter++      // becomes 2

// ... do work, calls transfer()

// Generated for transfer (NESTED)
%counter = load i32, @tm_nested_call_counter  // counter is now 1
if (counter == 0)  // This condition is FALSE
    // Would call tm_begin() again - but doesn't
else               // nested path - TAKEN
    counter++      // becomes 2
    // NO tm_begin() here

// ... do work

// Exit from transfer
counter = 2, decrement to 1
NO tm_end() called (counter != 1 in nested path)

// Back to do_transaction_work
counter = 1
Call tm_end()  // ← Called only once, as expected
counter = 0
```

### The Plugin's IR for transaction functions
```llvm
; Entry of transfer function
%counter = load i32, ptr @tm_nested_call_counter
%is_outer = icmp eq i32 %counter, 0
br i1 %is_outer, label %outer, label %nested

outer:
  call i32 @sigsetjmp(ptr @tm_jmpbuf, i32 0)
  store i32 1, ptr @tm_nested_call_counter
  call void @tm_begin()
  br label %cont

nested:
  %counter_inc = add i32 %counter, 1
  store i32 %counter_inc, ptr @tm_nested_call_counter
  br label %cont

cont:
  ; actual work happens here (tm_read_i4, tm_write_i4, etc.)
  ...

; Exit of transfer function
%counter_at_end = load i32, ptr @tm_nested_call_counter
%is_outer_at_end = icmp eq i32 %counter_at_end, 1
br i1 %is_outer_at_end, label %outer_end, label %nested_end

outer_end:
  call void @tm_end()
  br label %cleanup

nested_end:
  br label %cleanup

cleanup:
  %counter_dec = add i32 %counter_at_end, -1
  store i32 %counter_dec, ptr @tm_nested_call_counter
  ret
```

### Key Characteristics
- **MULTIPLE transaction boundaries** (one per @TX function)
- Each @TX function has its own `tm_begin()`/`tm_end()` wrapper
- Counter-based nesting prevents multiple actual `tinystm::begin()` calls
- But the current runtime's `tm_begin()` is checking `tinystm::current_tx_wbctl->active` which may be interfering

## Root Cause of Failure

### The Assertion Error
```
TINYSTM ASSERTION FAILED: nested not supported (tinystm_wbctl.hpp:75)
Assertion failed: (!tx->active)
```

### Why it Happens
Looking at the current `TinySTM_runtime.cpp`:

```cpp
void tm_begin()
{
    if (tm_longjmp_ret != 0) {
        return;
    }

    auto *tx = tinystm::current_tx_wbctl;
    if (tx && tx->active) {
        return;  // Nested call, don't call tinystm::begin()
    }

    tinystm::begin();  // ← This can be called even for nested calls
}
```

**The problem:** The condition `if (tx && tx->active)` is NOT reliable for detecting nested plugin calls because:
1. After the outer `tm_begin()` call, `tx->active` is TRUE
2. When a nested function (e.g., transfer) calls `tm_begin()`, we want to skip it
3. But the check `tx->active` might not properly distinguish between "retry after abort" and "nested call"
4. Or `current_tx_wbctl` might not be set correctly on first call

### The Broken Plugin Pattern

The plugin generates this entry logic for EVERY transaction-annotated function:

```llvm
%counter = load i32, ptr @tm_nested_call_counter
%is_outer = icmp eq i32 %counter, 0
%jmpret = load i32, ptr @tm_longjmp_ret
%is_retry = icmp ne i32 %jmpret, 0
%is_outer1 = or i1 %is_outer, %is_retry        ; ← THE BUG IS HERE
br i1 %is_outer1, label %outer, label %nested
```

The condition `(counter==0 OR jmpret!=0)` causes a catastrophic problem:

**Scenario: First Transaction, Then Abort+Retry**

1. **Initial call to `do_transaction_work` (outermost):**
   - counter=0, jmpret=0 → condition TRUE → goes to "outer" path
   - Sets counter=1, calls tm_begin() ✓

2. **Nested call to `transfer` (during outer transaction):**
   - counter=1, jmpret=0 → condition FALSE → goes to "nested" path
   - Increments counter to 2, skips tm_begin() ✓

3. **TinySTM detects conflict, aborts, longjmps back:**
   - Longjmp lands in `do_transaction_work`'s sigsetjmp
   - jmpret is now set to non-zero ✓
   - Execution resumes and counter is reset to 0

4. **Retry: Second call to `do_transaction_work`:**
   - counter=0, jmpret≠0 → condition TRUE → goes to "outer" path
   - Sets counter=1, calls tm_begin() ✓

5. **Retry: Second call to `transfer` (nested during retry):**
   - counter=1, jmpret≠0 → condition TRUE → **GOES TO OUTER PATH** ✗
   - Calls sigsetjmp and tm_begin() AGAIN
   - But `tinystm::begin()` assertion: `!tx->active` FAILS
   - **Transaction is already active!**

**The Result:** `TINYSTM ASSERTION FAILED: nested not supported`

---

### Why the Runtime Can't Fix This

The fix I attempted in `tm_begin()` to check `if (counter == 1)` before calling `tinystm::begin()` doesn't work because:

1. The plugin's broken condition `(counter==0 OR jmpret!=0)` causes nested functions to reach tm_begin() when they shouldn't
2. When a nested function reaches tm_begin() during retry, counter will be 1 (because it was incremented as a nested call)
3. So the check `if (counter == 1)` cannot distinguish between:
   - A truly outermost call (should call tinystm::begin())
   - A nested call during retry that shouldn't call tinystm::begin() (but counter is also 1!)

The nested function's counter is 1, but it shouldn't be calling tinystm::begin(). This is unfixable at the runtime level.
