\section{Worked Example: TLA+ to Code --- Finding and Fixing a Validation Bug}
\index{TLA+}\index{TLC}\index{counterexample}\index{validation bug}\index{NOrec}\index{model checking!trace to code}
\label{sec:tla-to-code}

The earlier worked example showed a deliberately broken NOrec-style commit
action (Listing~\ref{lst:broken-commit}) and the value-recheck guard it
omits (Listing~\ref{lst:commit-recheck}).  This section completes the loop:
the same stale-snapshot bug gets a full TLC counterexample, that trace is
followed into the actual C++ backend, and the fix is verified by re-running
TLC.

\subsection{The Broken Model}

The broken commit action of Listing~\ref{lst:broken-commit} is the one
mutation applied to the \texttt{BankNOrecValue} model earlier in this
chapter: delete the commit-time value recheck
(\texttt{r1 = bal[1] /\ r2 = bal[2]}) from inside the lock, and keep
everything else.

The guard \texttt{ok} was set earlier by the optimistic validation:
if the clock had not changed since the snapshot, \texttt{ok} became
\texttt{TRUE}.  But the commit action above does not re-read
\texttt{bal[1]} and \texttt{bal[2]} under the lock before writing back.
It trusts the cached snapshot values \texttt{r1} and \texttt{r2}
unconditionally.

\subsection{The TLC Counterexample}

TLC finds a short two-transaction trace.  The schedule is:

\begin{enumerate}
  \item Transaction~1 records \texttt{snap = 0} and reads
        \texttt{r1 = bal[1] = 10}, \texttt{r2 = bal[2] = 10}.
  \item Transaction~1's optimistic validation fires while the clock is
        still \texttt{0}: unchanged since \texttt{snap}, so
        \texttt{ok = TRUE}.
  \item Transaction~2 transfers 1 from account~1 to account~2 and
        commits: \texttt{bal = <<9, 11>>}, \texttt{clock = 1}.
  \item Transaction~1 enters the broken commit: the guard
        \texttt{ok /\ r1 >= amount} still holds on its cached values, so
        it acquires the lock and writes \texttt{bal[1] = 9 - 1 = 8},
        \texttt{bal[2] = 11 + 1 = 12} --- without rechecking that
        \texttt{bal} still matches what it read.
\end{enumerate}

The final state is \texttt{bal = <<8, 12>>}.  Money is conserved (20) and
the floors hold, yet the history admits \emph{no legal serialization}:
Transaction~1 committed against a read of \texttt{(10, 10)}, but no serial
order can give both transactions the values they read --- T1's reads must
precede T2's commit and its writes must follow it, and no replay under any
commit order reproduces \texttt{r1 = 10} for a transaction placed after
T2.  This is exactly a lost update.  Money conservation cannot see it (the
total survives); what catches it is the read-from legality invariant of
\S\ref{sec:histories-legality-opacity} --- recorded reads must match the
values a replay under the commit order produces, the same shape used by the
strongest invariant of the companion's models.  With that invariant in the
configuration, TLC reports:

\begin{lstlisting}[caption={TLC counterexample output (simplified).}]
Invariant NoStaleCommit violated (recorded reads fail replay under commit order).
State 5: bal = <<8, 12>>, clock = 1
  replay expects bal[1] = 9 for Tx 1's r1; recorded r1 = 10
\end{lstlisting}

Note what the counterexample buys and costs: a conservation-only run of the
same model passes this trace silently --- the total is still 20 --- which
is why the chapter's models carry a legality invariant, not just a sum.

\subsection{Tracing to C++}

The corresponding C++ implementation is
\rep{backends/tm\_impl/norec/NOrec.hpp}.
The \texttt{commit()} function (line~251) implements the protocol that
the TLA+ model checks.  The critical validation logic lives inside the
CAS retry loop:

\begin{lstlisting}[caption={Simplified NOrec commit path (\texttt{NOrec.hpp:251}).}]
inline void commit() {
  auto *tx = current_tx;
  if (tx->read_only) { tx->reset(); return; }

  word_t expect = tx->snapshot;
  while (!global_lock.compare_exchange_strong(
             expect, expect + 1,
             std::memory_order_acquire,
             std::memory_order_relaxed)) {
    // CAS failed: clock changed.  Re-check values.
    tx->snapshot = validate();
    expect = tx->snapshot;
  }
  // Lock acquired.  Write back.
  for (auto &w : tx->write_set)
    write_value_to_addr(w.addr, w.new_val, w.type);
  set_clock(expect + 2);       // release lock, advance clock
  tx->reset();
}
\end{lstlisting}

The \texttt{validate()} function (line~227) is where the value recheck
happens:

\begin{lstlisting}[caption={The value validation that the broken model omitted.}]
inline word_t validate() {
  auto *tx = current_tx;
  volatile word_t time = 0;
  while (true) {
    time = get_clock();
    if ((time & 1) != 0) continue;     // lock held, spin
    for (auto &r : tx->read_set) {
      any_type_t check =
          read_value_from_addr(r.addr, r.type);
      if (!iseq(check, r.observed_val))  // THE CRITICAL CHECK
        abort_tx();                      // stale read -> abort
    }
    if (time == get_clock()) return time;  // clock stable
  }
}
\end{lstlisting}

If the line \texttt{if (!iseq(check, r.observed\_val)) abort\_tx();}
were removed, the function would always succeed: the read-set entries
would be walked but never actually checked.  A transaction that read
stale values would proceed to write-back and publish incorrect results
--- the same bug the TLA+ model exposed.

The connection between model and code is direct:

\begin{itemize}
  \item The broken commit action's missing recheck corresponds to
        removing the \texttt{iseq()} comparison in
        \texttt{validate()}.
  \item The CAS retry in the C++ code corresponds to the
        \texttt{Validate} branch of the \texttt{BankNOrecValue} model
        above: if the clock changed since the snapshot, the transaction
        must re-validate (\texttt{ok := (r1 = bal[1] /\ r2 = bal[2])})
        before attempting the commit again.
  \item The value-based comparison (\texttt{iseq}) is the same check
        that the correct model encodes as
        \texttt{r1 = bal[1] /\ r2 = bal[2]}.
\end{itemize}

\subsection{The Fix}

The fix in the model is to restore the value recheck: re-add the guard of
Listing~\ref{lst:commit-recheck}
(\texttt{clock = snap /\ r1 = bal[1] /\ r2 = bal[2]}) inside the commit
action, under the lock.

In the C++ code, the recheck already exists as the \texttt{iseq()} test
inside \texttt{validate()}.  The lesson is that the model and the code
encode the same safety argument in different notation.  When someone
removes the recheck from the model, TLC catches the bug.  If someone
removes the corresponding line from \texttt{NOrec.hpp}, the bank
benchmark loses money --- the same invariant that TLC checked, violated
in the real implementation.

\subsection{Re-running TLC}

After restoring the recheck, TLC re-runs and confirms the fix:

\begin{lstlisting}[caption={TLC output after the fix is restored.}]
Model checking completed.  No errors found.
149430 states generated, 64891 distinct states.
\end{lstlisting}

The model and the code agree: the value recheck is the single line
that separates a correct NOrec from a stale-snapshot mutation.  This is
the end-to-end workflow of \S\ref{sec:verify-workflow}: specify, check,
inject a bug, confirm the checker finds it, trace the result to code,
fix, and re-check.
